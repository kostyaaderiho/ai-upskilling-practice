# Shelf

Личная книжная полка — небольшое Express-приложение (модуль 3).
Задачи и известные баги лежат в [BACKLOG.md](BACKLOG.md).

## Стек

- **TypeScript**, строгий режим (`strict: true`), только ESM (`"type": "module"`).
- **Node.js** (типы `@types/node`), запуск через **tsx**.
- **Express 5** — единственная рантайм-зависимость.
- **Vitest** + **supertest** — тесты и HTTP-проверки.
- **ESLint 9** (flat config, `typescript-eslint` recommended).
- Хранилище — in-memory `Map` в [src/storage.ts](src/storage.ts), без БД.
  Данные живут только в рамках процесса.

Раскладка: `src/` — код (`app.ts` роуты, `storage.ts` данные, `stats.ts`
расчёты, `log.ts` логгер, `server.ts` точка входа), `tests/` — тесты,
`docs/` — заметки.

## Команды

| Команда            | Что делает                                   |
|--------------------|----------------------------------------------|
| `npm install`      | установка зависимостей                       |
| `npm run dev`      | dev-сервер с watch на `http://localhost:3000` (порт из `PORT`) |
| `npm run typecheck`| `tsc --noEmit`                               |
| `npm run lint`     | `eslint .`                                   |
| `npm test`         | `vitest run`                                 |
| `npm run check`    | всё вместе: tsc + eslint + vitest            |

Перед тем как считать задачу готовой, прогоняй `npm run check` и сообщай
настоящий результат.

## Конвенции

- **Логирование — только через `getLogger()` из [src/log.ts](src/log.ts).**
  Никаких `console.log` / `console.error` в коде приложения:

  ```ts
  import { getLogger } from "./log";

  const log = getLogger("app");
  log.info("mark read succeeded", { id, title: book.title });
  ```

  Доступны уровни `info`, `warn`, `error`. Первый аргумент — короткое
  человекочитаемое сообщение, второй — объект с контекстом (id, параметры
  запроса, текст ошибки). Логгер пишет одну JSON-строку в stdout, поэтому
  контекст передавай полями объекта, а не склейкой в строку.

- **Ошибки API — объект `{ detail }` плюс соответствующий статус-код:**

  ```ts
  res.status(404).json({ detail: "Book not found" });
  ```

  Формат одинаковый для всех ошибок: 400 при некорректном вводе, 404 при
  отсутствии ресурса и так далее. Никаких других форм (`{ error }`,
  `{ message }`, голая строка) и никаких ошибок со статусом 200.

- **Тесты лежат в `tests/`**, имя файла — `*.test.ts`. Приложение
  импортируется как `import { app } from "../src/app"` и проверяется через
  `supertest`, без подъёма реального сервера. Новая ручка или исправленный
  баг — значит, новый тест в `tests/`.

- Ошибки домена — отдельные классы в `src/storage.ts`
  (например `BookNotFoundError`), а роут переводит их в HTTP-статус.

- Исходники держим на TypeScript со строгой типизацией: без `any` и без
  `@ts-ignore`; публичные функции — с явным возвращаемым типом.

## Запреты

- **Не менять файлы вне задачи.** Правим только то, что требует текущая
  задача. Замеченные рядом проблемы — не трогаем молча, а называем их в
  ответе (или добавляем в `BACKLOG.md`, если попросили).
- **Не добавлять зависимости без запроса.** Никаких новых пакетов в
  `package.json` (включая dev-зависимости) без явного согласия. Если задача
  выглядит так, что без библиотеки не обойтись — сначала спроси.
- **Не делать `push` и `merge`.** Коммит, пуш, слияние ветки, открытие MR —
  только по прямой просьбе. По умолчанию работа остаётся в рабочем дереве.
- Не менять контракт существующих ручек (коды ответов, формат тела) заодно
  с другой задачей — это отдельное решение, его принимает человек.
- Не ослаблять проверки, чтобы «стало зелёным»: не правим `eslint.config.js`
  и `tsconfig.json` и не удаляем тесты ради прохождения `npm run check`.
