## User Scenarios & Testing *(mandatory)*

### User Story 1 - Выгрузка библиотеки в JSON (Priority: P1)

Владелец полки запрашивает экспорт в формате JSON и получает все свои книги в виде
машинно-читаемого документа, пригодного для резервной копии или переноса в другой инструмент.

**Why this priority**: JSON — основной и самый простой формат; даёт ценность сам по себе (MVP).

**Independent Test**: Добавить несколько книг, запросить экспорт в JSON и сверить содержимое
с текущим списком книг.

**Acceptance Scenarios**:

1. **Given** в библиотеке есть книги, **When** запрошен экспорт в JSON, **Then** ответ содержит
   каждую книгу с её идентификатором, названием, автором и признаком «прочитана».
2. **Given** библиотека пуста, **When** запрошен экспорт в JSON, **Then** результат — валидный
   пустой список, а не ошибка.

---

### User Story 2 - Выгрузка библиотеки в CSV (Priority: P2)

Владелец полки запрашивает экспорт в формате CSV, чтобы открыть библиотеку в таблице.

**Why this priority**: Удобно для людей и таблиц, но зависит от уже определённого состава данных
из истории 1.

**Independent Test**: Добавить книги (в том числе с запятой и кавычками в названии), запросить CSV
и убедиться, что таблица открывается без искажения полей.

**Acceptance Scenarios**:

1. **Given** в библиотеке есть книги, **When** запрошен экспорт в CSV, **Then** первая строка —
   заголовки столбцов, далее по одной строке на книгу с теми же данными, что и в JSON.
2. **Given** библиотека пуста, **When** запрошен экспорт в CSV, **Then** результат содержит
   только строку заголовков.
3. **Given** у книги в названии есть запятая, кавычки или перевод строки, **When** запрошен
   экспорт в CSV, **Then** значение экранировано, и книга занимает ровно одну запись.

---

### User Story 3 - Понятная ошибка при неверном формате (Priority: P3)

Если формат не указан или не поддерживается, пользователь получает понятное сообщение об ошибке,
а не пустой или неверный результат.

**Why this priority**: Защитный сценарий; не даёт ценности без историй 1–2.

**Independent Test**: Запросить экспорт с неизвестным и с отсутствующим форматом и проверить ответ.

**Acceptance Scenarios**:

1. **Given** любое состояние библиотеки, **When** запрошен неизвестный формат, **Then** возвращается
   ошибка в стандартной форме `{ detail }` с кодом 400.
2. **Given** формат в запросе не указан, **When** запрошен экспорт, **Then** возвращается та же ошибка.

---

### Edge Cases

- Пустая библиотека: JSON — пустой список, CSV — только заголовки.
- Названия и авторы со спецсимволами (запятая, кавычки, перевод строки, не-ASCII символы).
- Регистр значения формата (`JSON`, `Csv`) — считается неизвестным форматом (см. Assumptions).
- Экспорт не должен изменять данные библиотеки.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST позволять запросить экспорт библиотеки в формате JSON или CSV через
  `GET /books/export?format=json|csv`.
- **FR-002**: Экспорт в обоих форматах MUST содержать одинаковый набор данных по каждой книге:
  идентификатор, название, автор, признак «прочитана».
- **FR-003**: Экспорт MUST включать все книги библиотеки независимо от признака «прочитана»;
  фильтрация по этому признаку вне объёма фичи.
- **FR-004**: CSV MUST начинаться со строки заголовков и корректно экранировать значения
  с запятыми, кавычками и переводами строк.
- **FR-005**: Для пустой библиотеки система MUST возвращать успешный ответ: пустой список (JSON)
  или только заголовки (CSV).
- **FR-006**: Для неизвестного или отсутствующего формата система MUST возвращать ошибку
  в форме `{ detail }` с кодом 400 и не возвращать данных.
- **FR-007**: Экспорт MUST быть операцией только для чтения и не требовать внешних сервисов
  или сетевых вызовов.
- **FR-008**: Реализация MUST обойтись без новых зависимостей (формат CSV формируется
  собственным кодом).
- **FR-009**: Новая ручка и каждый сценарий выше MUST быть покрыты тестами, написанными
  до реализации (пустая библиотека, оба формата, неверный формат).

### Key Entities *(include if feature involves data)*

- **Книга**: запись библиотеки; атрибуты — идентификатор, название, автор, признак «прочитана».
- **Экспорт**: снимок набора книг в выбранном формате на момент запроса.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Владелец получает полный экспорт библиотеки одним запросом, без дополнительных шагов.
- **SC-002**: В 100% проверочных запросов данные в JSON и CSV совпадают с текущим списком книг
  по составу и значениям полей.
- **SC-003**: CSV с книгами, содержащими запятые, кавычки и переводы строк, открывается в таблице
  без смещения столбцов.
- **SC-004**: В 100% запросов с неверным или отсутствующим форматом пользователь получает
  понятное сообщение об ошибке и никаких данных.

## Assumptions

- Значение `format` чувствительно к регистру: допустимы только `json` и `csv` в нижнем регистре.
- Экспорт охватывает всю библиотеку без пагинации (хранилище небольшое и in-memory).
- Состав полей экспорта совпадает с текущей моделью книги; новые поля появятся в экспорте
  вместе с моделью.
- Аутентификации в проекте нет; экспорт доступен так же, как остальные ручки.
- Декомпозиция из docs/B-4.md (формат → функция экспорта → ручка → тесты) используется
  как порядок работ на этапах плана и задач.
