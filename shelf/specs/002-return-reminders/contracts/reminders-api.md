# Contract: срок возврата и напоминания

Все ошибки — `{ "detail": "<текст>" }` с соответствующим статус-кодом. Номер книги в пути
разбирается как в `POST /books/:id/read`.

## PUT /books/:id/due

Задаёт или заменяет срок возврата.

Тело запроса:

```json
{ "dueDate": "2026-11-20" }
```

| Поле | Обязательно | Допустимые значения |
|------|-------------|---------------------|
| `dueDate` | да | строка `YYYY-MM-DD`, существующая календарная дата; прошлая дата допустима |

Ответы:

- `200` — книга целиком:
  `{ "id": 1, "title": "Дюна", "author": "Фрэнк Герберт", "read": false, "dueDate": "2026-11-20" }`.
- `400` — `dueDate` отсутствует, не строка, в другом формате или несуществующая дата
  (например `2026-02-31`). Книга не меняется.
- `404` — `{ "detail": "Book not found" }`.

## POST /books/:id/return

Снимает срок возврата. Тела запроса нет.

Ответы:

- `200` — книга целиком без поля `dueDate`. У книги, которая и так не была взята, — тот же
  ответ, без ошибки.
- `404` — `{ "detail": "Book not found" }`.

## GET /books/reminders

Тела и параметров нет. Окно напоминания фиксировано (3 дня) и не настраивается.

Ответ `200` — массив, от самого раннего срока к позднему, при равных сроках по `id`:

```json
[
  { "id": 2, "title": "Солярис", "dueDate": "2026-11-09", "status": "overdue" },
  { "id": 1, "title": "Дюна", "dueDate": "2026-11-12", "status": "due-soon" }
]
```

| `status` | Условие |
|----------|---------|
| `overdue` | срок раньше сегодняшней даты |
| `due-soon` | срок сегодня или в ближайшие 3 дня |

Нет ни одной подходящей книги — `[]`, не ошибка. Книги без срока и со сроком позже чем через
3 дня в список не входят. «Сегодня» — локальная дата машины, на которой запущено приложение.

## Совместимость

Существующие ручки и их ответы не меняются. У книги без срока поле `dueDate` отсутствует,
поэтому `POST /books`, `GET /books`, `GET /books/:id`, экспорт и статистика отвечают как раньше.
