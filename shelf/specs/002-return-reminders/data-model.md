# Data Model: Напоминания о возврате книг

## Book (существует, `src/storage.ts`; расширяется)

| Поле | Тип | Правило |
|------|-----|---------|
| `id` | number | без изменений |
| `title` | string | без изменений |
| `author` | string | без изменений |
| `read` | boolean | без изменений; не зависит от возврата |
| `dueDate` | string (необязательное) | `YYYY-MM-DD`, существующая календарная дата; отсутствует, пока книга не взята |

Инвариант: `dueDate` либо отсутствует, либо содержит корректную дату. Поле не создаётся
пустым или `null`, поэтому тела существующих ответов не меняются.

### Состояния

```text
не взята (dueDate нет) --PUT /books/:id/due--> взята (dueDate = D)
взята (D)              --PUT /books/:id/due--> взята (D')       замена срока
взята (D)              --POST /books/:id/return--> не взята     срок снят
не взята               --POST /books/:id/return--> не взята     без ошибки
```

## Новые типы (`src/storage.ts`)

- `ReminderStatus` = `"overdue" | "due-soon"`.
- `Reminder` = `{ id: number; title: string; dueDate: string; status: ReminderStatus }`.
- `InvalidDueDateError` — доменная ошибка некорректной даты возврата.
- `REMINDER_WINDOW_DAYS` = `3`.

## Reminder (производная, не хранится)

Строится при запросе из книг, у которых есть `dueDate`:

| Условие (`left` — дней от сегодня до срока) | Результат |
|---------------------------------------------|-----------|
| `left < 0` | в списке, `status = "overdue"` |
| `0 <= left <= 3` | в списке, `status = "due-soon"` |
| `left > 3` или `dueDate` нет | не попадает |

Порядок: `dueDate` по возрастанию, затем `id`. Запрос не изменяет `books`.
